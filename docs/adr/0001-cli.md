# ADR-0001: Initial CLI Architecture

Date: 2026-11-22
Status: Proposed

## Context
The project requires a small, testable Python application
that analyzes synthetic log files and produces JSON reports.

## Decision
- Start with a single Python file: log_analyzer.py.
- Use Python 3.12 and standard library components.
- Keep CLI, parsing, classification, and reporting
  as identifiable responsibilities.
- Use pytest for automated testing.
- Avoid web services, databases, and microservices.
- Introduce a package structure only when justified.

## Alternatives
1. Single Python file: simplest initial approach.
2. Python package: useful when complexity increases.
3. Web service: unnecessary for the current requirements.

## Consequences
Positive:
- Simple development and execution.
- Low dependency and maintenance overhead.
- Easy local testing.

Negative:
- A single file may become harder to maintain as it grows.
- Future modularization may require refactoring.

## Revisit When
- The code becomes difficult to maintain.
- Multiple interfaces need to reuse the same logic.
- Packaging becomes a confirmed requirement.
